# Products and Categories

Phase 4 implements descriptive catalogue data only. `Category` organizes `Product`; ordered `ProductImage` and `ProductSpecification` records hold media metadata and public specifications. Products have stable globally unique slugs, a category, short and long descriptions, a descriptive rental unit, active and featured flags, and timestamps. No price, quantity, availability, reservation, or inventory state exists in these models.

Public URLs are `/rentals`, `/rentals/{categorySlug}`, and `/rentals/{categorySlug}/{productSlug}`. Slugs are lowercase ASCII words separated by single hyphens. Authorized staff may edit a category slug; input is trimmed, lowercased, validated, and kept globally unique. Renaming a category does not regenerate its slug. Changing a slug changes the public category and product URLs immediately; old URLs do not redirect because the platform has no redirect registry yet.

Administrative product create/update operations validate strict shared Zod metadata contracts. Specifications are replaced in their documented order. Product metadata payloads cannot associate or remove images: uploads, alt-text/primary changes, ordering, and removal are exclusive to the separately authorized media endpoints and authoritative Sharp pipeline. This prevents arbitrary URLs and metadata edits from bypassing image validation. PostgreSQL enforces unique ordered positions and at most one primary image.

Deactivation and permanent deletion are separate operations. `POST /admin/categories/{id}/deactivate` hides a category reversibly and reactivation is explicit. A category cannot be deactivated while it contains active products, and an active product cannot be created, moved, or reactivated beneath an inactive category.

`DELETE /admin/categories/{id}` permanently removes the category from active catalogue management. An empty category is hard-deleted. A non-empty category requires `confirmDeleteProducts`; the server recalculates dependencies inside the transaction and never trusts a client count. Unreferenced products are hard-deleted with their database media metadata, specifications, carts, and unused inventory configuration. Committed media files are cleaned up only after the transaction succeeds.

Products referenced by requests, revisions, change requests, inventory items, reservations, or transactions are marked with `deletedAt`, made inactive and non-featured, and retained as historical tombstones. Their category is also tombstoned. Tombstones are excluded from active admin/public lists and cannot enter new carts or requests, but restrictive foreign keys, inventory history, commercial snapshots, fulfilment/return history, and stored media needed by history remain intact. Tombstone slugs remain reserved. Quote and order lines already use immutable snapshots and are never cascaded by catalogue deletion.

The local-only `pnpm catalogue:seed` command creates two categories and two descriptive sample products by stable slug. It never changes, reactivates, reassigns, or deletes existing records and refuses non-development environments. It creates no inventory or pricing data.

Product edit pages upload at most four JPEG, PNG, or WebP images. The browser validates the 10 MB source limit, preserves aspect ratio, avoids enlargement, resizes to a maximum 2400-pixel longest side, and attempts WebP compression at reasonable qualities. The API independently inspects content with Sharp, applies EXIF orientation, strips unnecessary metadata, enforces dimensions and the 2 MB processed limit, and stores only normalized WebP assets. Browser processing is an optimization; server validation is authoritative.

Development files live under the ignored `MEDIA_STORAGE_ROOT` and are exposed only through content-hash `/media/products/...` URLs. Internal disk paths never enter API responses. Web and admin applications proxy those public media paths to the API. Production should replace local disk with durable object storage while preserving the public URL/storage abstraction.

Phase 6 adds public semantic sorting (`featured`, `name-asc`, `name-desc`, and `newest`), server-side descriptive search, featured filtering, numbered pagination, and bounded related products. Category selection continues to use slug routes. Active empty categories remain public so a temporarily empty published category does not disappear from navigation. Product list projections carry one image for efficiency; detail projections carry at most four ordered images. See [Customer catalogue](customer-catalogue.md).

## Phase 16.3 product correction

Authorized staff may edit a product name and slug. Product slugs are trimmed, lowercased, validated as lowercase words separated by single hyphens, and remain globally unique. Renaming a product does not regenerate its slug. Changing the slug changes its public URL immediately; old URLs return 404 because no redirect registry exists yet. Category, rental unit, descriptions, specifications, featured state, publication state, media, and inventory links remain intact during metadata edits.

Product deactivation and deletion are separate. `POST /admin/products/{id}/deactivate` is reversible and requires `product.update`; `DELETE /admin/products/{id}` is irreversible catalogue removal and requires `product.delete`. The API performs a non-mutating dependency preflight, then recalculates the result under catalogue, product, and row locks when confirmation is submitted. An unreferenced product and empty inventory configuration are hard-deleted. Any request, revision, change-request, serialized-asset, reservation, or inventory-transaction dependency forces tombstone retention.

Hard-deleted products have cart lines, specifications, media metadata, and safe empty inventory configuration removed transactionally; committed local media cleanup starts only after commit. Tombstoned products become inactive and non-featured, retain required media and operational identity, and disappear from normal administrative/public catalogue surfaces. Deletion never changes inventory quantities, releases reservations, changes fulfilment or return state, or resolves issues.
